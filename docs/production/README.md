# Production planning

This directory contains the repeatable planning and validation practices used
to move *Dam it!* through its roadmap milestones.

- [Playtest method](playtest-method.md) explains how to run comparable,
  low-overhead tests without requiring a moderated session.
- [Feedback form](playtest-feedback-form.md) is the short questionnaire sent to
  a tester after a session.
- [Current demo baseline](current-demo-baseline.md) records the starting point
  against which the Act I vertical slice will be evaluated.
- [Dam economy notes](dam-economy-notes.md) records the before/after
  resource-action budget for the issue #19 gathering/dam retune.
- [Act I presentation and readability audit](act1-presentation-readability-audit.md)
  prioritizes the Web UI findings, directional movement slice, audio-state
  contract, and final validation gate for issue #9.

Milestone 1 implementation work is tracked in the
[Act I narrative vertical slice milestone](https://github.com/CrowderSoup/dam-it/milestone/1).
Each issue states its first concrete next action, so an unassigned issue is
still actionable for a solo developer. The first implementation issue should
be [safe, discoverable controls](https://github.com/CrowderSoup/dam-it/issues/22),
followed by the
[shared interaction contract](https://github.com/CrowderSoup/dam-it/issues/7)
and
[dialogue/objective foundation](https://github.com/CrowderSoup/dam-it/issues/12).
